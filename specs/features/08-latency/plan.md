# Feature 8 plan: Latency

The steps follow the answers to G1 to G6 in requirements.md.

1. Take the first two server timestamps. The broadcaster gets a clock function that returns the microseconds since the Unix epoch, and tests replace it. A new method makes one batch. It reads the clock, asks the generator for the values, and publishes them. `publish` reads the clock after it encodes the text. The batch holds `started` and `encoded` next to the sequence number and the text. The run loop calls the new method. This step changes backend/app/broadcaster.py.
2. Build the id and add the time endpoint. The stream route reads the clock when it takes a batch from the queue, and it sends the id in the form from G2. `GET /time` returns the server time in the form from G3, with a header that stops a cache from keeping it. This step changes backend/app/main.py.
3. Write the backend tests. The stream tests from features 2, 6, and 7 that read a batch id now read the sequence number from the first part. The two tests that compare the ids of two clients now compare the first three parts, because each client has its own `sent` time. This step changes backend/tests/test_broadcaster.py and backend/tests/test_stream.py, and it creates backend/tests/test_time.py.
4. Read the id on the client. A function takes the id text and returns the sequence number and the three server times in milliseconds, or the sequence number alone. This step creates frontend/src/app/source/batch-id.ts and frontend/src/app/source/batch-id.spec.ts.
5. Add the percentile function. It takes a list of numbers and returns the p50, the p95, the p99, and the max by the nearest rank method. This step creates frontend/src/app/latency/latency-stats.ts and frontend/src/app/latency/latency-stats.spec.ts.
6. Add the clock sync. A function picks the offset from the request with the shortest round trip. A service makes the 5 requests at start and each time the tracker resets, and it holds the offset and the round trip. The source settings give the address of `GET /time`. This step creates frontend/src/app/latency/clock-sync.ts and frontend/src/app/latency/clock-sync.spec.ts, and it changes frontend/src/app/source/source-settings.ts and frontend/src/app/source/source-settings.spec.ts.
7. Add the latency tracker. A service takes the times of each batch, holds the batch until a frame draws it, and then stores the seven stage times and the total. It builds the report and the reset from G4, and a reset also starts a new clock sync. A function sets `window.latency`. This step creates frontend/src/app/latency/latency-tracker.ts and frontend/src/app/latency/latency-tracker.spec.ts.
8. Take the `received`, `parsed`, and `applied` times in the server source. The message handler reads the clock at its start, after the parse, and after the counts change. It passes the sequence number to the missed batch counter, and it passes the times to the tracker. This step changes frontend/src/app/source/server-source.ts and frontend/src/app/source/server-source.spec.ts.
9. Take the `frame` and `drawn` times in the heat map component. The frame callback reads the clock at its start and after the draw call, and it passes both times to the tracker when the frame draws. A draw on a resize passes nothing. This step changes frontend/src/app/heatmap/heat-map.ts and frontend/src/app/heatmap/heat-map.spec.ts.
10. Start the clock sync and set `window.latency` when the app uses the server source. This step changes frontend/src/app/app.ts and frontend/src/app/app.spec.ts.
11. Update the README. The Backend stream section describes the new id and `GET /time`. The Client section gets a Latency part that names the stages and tells how to read the report. The Specs and logs section names docs/results.md. This step changes README.md.
12. Run the automated checks in validation.md and fix the failures.
13. Measure and write the results. I stop and ask the user to deploy, to do the two runs from G5, and to paste the two reports. I then write the file from the reports. This step creates docs/results.md.
14. Add entries for this feature to the three logs. This step changes docs/assumptions.md, docs/trade-offs.md, and docs/ai-changes.md.
