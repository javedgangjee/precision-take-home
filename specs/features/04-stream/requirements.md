# Feature 4 requirements: Stream

## Requirements from the sources

- R1. The client reads the stream of nonnegative integers from the server over Server-Sent Events and applies each batch to the counts. (B2; tech-stack.md, Backend)
- R2. The client shows one of three stream states, which are Live, Connecting, and Reconnecting. (N10)
- R3. The client reconnects with backoff after the stream drops. (N10)
- R4. The counts stay on screen while the client reconnects. (N9)
- R5. A badge at the top of the side panel shows the stream state, as in the HTML design. (D1)
- R6. A Dockerfile builds the backend image, and the same image runs in Docker Desktop on my laptop and on ECS Fargate with ARM64 in feature 5. (roadmap feature 4; tech-stack.md, Backend and Infrastructure)
- R7. A Makefile target runs the backend image in Docker Desktop, so the client can connect to it. (roadmap feature 4, N13)
- R8. The user can still pick the test source from feature 3. (feature 3, G2; docs/assumptions.md)
- R9. The README and the three logs in docs/ record this feature. (roadmap, S3, S7, N14; CLAUDE.md)

## Items the sources do not cover

Each item below was my proposal. The user answered each one.

- G1. **Agreed with a change.** The client uses the server by default. The URL query `source=frontend` runs the test source from feature 3 instead, with its `rate`, `interval`, and `max` settings. The user chose the name `frontend`. Only one source runs at a time. Any other value of `source` logs a warning and uses the server. With the test source, the badge shows "Test source" in the neutral tone, so a reviewer cannot mistake it for the server.
- G2. **Agreed.** The client reads the server address from the URL query `server`, and the default is http://localhost:8000. The client strips a trailing slash and connects to the address plus `/stream`. A value that is not an http or https URL logs a warning and uses the default. Feature 5 changes the default to the cloud URL, https://api.precision.jgangjee.com.
- G3. **Agreed.** The state is Connecting from the start until the first `open` event. It is Live after an `open` event. When the stream drops after it was Live, the state is Reconnecting until the next `open` event. A failed first attempt keeps the state at Connecting. The stream code never resets the counts. Only a change to N resets them.
- G4. **Agreed.** EventSource retries on its own at a fixed delay, with no backoff. So on each `error` event the client closes the EventSource and makes a new one after a delay. The delay is min(30 s, 1 s × 2^k) × f, where k is the number of failed attempts since the last `open` event and f is a random factor from 0.5 to 1. The random factor stops many clients from reconnecting at the same moment after a server restart. A new EventSource sends no `Last-Event-ID` header, so the preflight concern in docs/assumptions.md goes away.
- G5. **Agreed.** EventSource hides SSE comments, so the client cannot see the `: ping` heartbeat. At the lowest server settings, a batch arrives at least once each second. So the client treats the stream as dropped when no batch arrives for 5 s while the state is Live, and it reconnects with the backoff from G4. This catches a connection that hangs without an `error` event.
- G6. **Agreed with a change.** The badge follows the `md-badge` style in the HTML design. It is a pill at the top of the side panel, with an hr line below it. Connecting uses the neutral tone, which is outlined. Live uses the success tone, which is a #157A42 fill. Reconnecting uses the warning tone, which is a #95560F fill. The user asked for Material Symbols icons that match each state. Connecting uses `progress_activity`, Live uses `sensors`, and Reconnecting uses `sync`. The bundled font subset has only the add and remove glyphs. The user chose not to add fonttools and chose a Google Fonts link instead. src/index.html loads `https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght@20,300&icon_names=add,progress_activity,remove,sensors,sync`, which serves only these five icons. The implement step removes frontend/public/fonts/material-symbols-outlined.woff2 and its @font-face rule, so one font serves all the icons. This changes feature 3 G9 for the icons only, and the client now needs the network for them. The text fonts stay bundled. The Test source badge has no icon.
- G7. **Agreed.** The new client code lives in frontend/src/app/source/ and frontend/src/app/panel/. The file source-settings.ts reads `source` and `server` from the query. The file backoff.ts holds the delay function. The file stream-status.ts is a small injectable service that holds the state as one signal. The source in use writes it, and the badge reads it. The file server-source.ts is the service that owns the EventSource, the backoff timer, and the watchdog. An injection token makes the EventSource, so the tests use a fake, as the test source does with its worker. The panel/stream-badge component shows the badge.
- G8. **Agreed.** The Dockerfile is backend/Dockerfile and has two stages. The build stage starts from python:3.13.15-slim, copies uv 0.11.24 from ghcr.io/astral-sh/uv:0.11.24, and runs `uv sync --frozen --no-dev`. The run stage starts from python:3.13.15-slim, copies the virtual environment and backend/app/, and runs as a user that is not root. It runs `uvicorn app.main:app --host 0.0.0.0 --port 8000 --timeout-graceful-shutdown 3`, so `docker stop` ends it within 3 s. The image targets linux/arm64, which is native on my laptop and matches Fargate ARM64. A backend/.dockerignore file keeps .venv, tests, and caches out of the build.
- G9. **Agreed.** `make docker-build` builds the image with the tag `precision-backend`. `make docker` builds the image and runs it with `docker run --rm -p 8000:8000`. It passes `SAMPLES_PER_SECOND`, `BATCH_INTERVAL_MS`, `MAX_VALUE`, and `CORS_ORIGINS` into the container when they are set in the shell. Ctrl+C stops the container. `make docker` and `make backend` both use port 8000, so the client needs no change to use either.
- G10. **Added by the user.** The client never sends `Last-Event-ID`, because G4 makes a new EventSource for each reconnect. So the backend drops `allow_headers=["Last-Event-ID"]` from its CORS rule and the comment above it, and the test `test_cors_preflight_allows_last_event_id` goes. The comment in the stream route that says the server ignores `Last-Event-ID` goes as well. The server still sends the sequence number in the `id` field, as N5 says.
