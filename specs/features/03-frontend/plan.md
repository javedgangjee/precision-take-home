# Feature 3 plan: Frontend

The steps follow the answers to G1 to G10 in requirements.md. All paths are under frontend/ unless a step says otherwise. Each step that adds code also adds its spec file next to it.

1. Extract the six woff2 fonts from the design bundle into public/fonts/. Write the design tokens, the font faces, and the page styles from the HTML design into src/styles.scss. Set the page title to "Bin There, Done That". This step creates public/fonts/ and changes src/styles.scss and src/index.html.
2. Write the binning functions. `binIndex(v, n)` returns (v - 1) mod N² and handles 0. `cellOf(v, n)` returns the row and the column. This step creates src/app/heatmap/binning.ts.
3. Write the counts class. It holds N, a Float64Array of N² counts, the max count, and the total samples. `apply(values)` bins each value, adds 1 to its cell, and updates the max and the total. `reset(n)` makes new zero counts. This step creates src/app/heatmap/grid-counts.ts.
4. Write the color map and the scale labels. `colorPosition(count, max)` returns null for a count of 0 and (count - 1) / (max - 1) otherwise, or 0 when the max is 1. A 256-entry table holds the colors from blue to red. `scaleLabels(max)` returns the labels from G4. This step creates src/app/heatmap/color-map.ts.
5. Write the grid layout functions. `labelStep(n)` returns the step from G5. `cellRect(row, col, n, size)` returns the pixel box of a cell with row 0 at the bottom and a 1 device pixel gap between cells. This step creates src/app/heatmap/grid-layout.ts.
6. Write the frame rate meter. `tick(now)` counts frames and returns the count of the last full second. The meter also reports when the reading is below 90 percent of the fixed target of 60 fps. This step creates src/app/heatmap/frame-rate.ts.
7. Write the store. It is an injectable service and the only owner of the heat map state. It holds N as a signal, the counts, the frame rate meter, the dirty flag, and the readout signals for the samples, the max count, the frame rate, and the error line. `setN(n)` clamps N to 1 to 64, resets the counts, and marks the grid dirty. `applyBatch(values)` updates the counts and marks the grid dirty. `frame(now)` ticks the meter, updates the readout signals at most every 150 ms, and returns true when the grid needs a redraw. This step creates src/app/heatmap/heat-map-store.ts.
8. Write the renderer. It is a plain class with no Angular code. `draw(ctx, counts, size)` fills the gap color, fills each cell with its color or white from the color map, and writes the axis labels at the step from G5. It uses `cellRect` from step 5, so row 0 is at the bottom. This step creates src/app/heatmap/heat-map-renderer.ts.
9. Write the heat map component. It is thin. It hosts the canvas and sizes it to a square that fits the main area with a ResizeObserver and the device pixel ratio. It runs one requestAnimationFrame loop that calls `store.frame(now)` and, when that returns true, `renderer.draw`. It stops the loop and the observer when it is destroyed. This step creates src/app/heatmap/heat-map.ts, heat-map.html, and heat-map.scss.
10. Write the color scale component. It is thin. It shows the bar with the gradient from G3 at the height of the grid and the labels from `scaleLabels(store.max())`. This step creates src/app/heatmap/color-scale.ts, color-scale.html, and color-scale.scss.
11. Write the side panel component. It is thin. It binds the store signals and calls `store.setN` from the N control in G8. It shows the three readouts and the red error line below the frame rate from G7, with hr lines between them as in the HTML design. This step creates src/app/panel/side-panel.ts, side-panel.html, and side-panel.scss.
12. Replace the Angular placeholder app with the page shell. It has the header, the main area with the heat map, and the side panel. This step changes src/app/app.ts, app.html, app.scss, and app.spec.ts.
13. Write the test source settings. `readTestSourceSettings(query)` reads `rate`, `interval`, and `max` from the URL query, applies the ranges and the defaults, and logs a warning for each bad value. This step creates src/app/source/test-source-settings.ts.
14. Write the batch generator. It takes the settings and returns the next batch as a JSON string of uniform integers from 0 to the max value minus 1. It carries the fractional sample count to the next call and returns null when a call has no samples. This step creates src/app/source/batch-generator.ts.
15. Write the worker and the service that starts it. The worker runs the generator on a timer at the batch interval and posts each JSON string. The service reads the settings from the page URL, starts the worker, parses each string, and calls `applyBatch`. The app starts the service at start. This step creates src/app/source/test-source.worker.ts, src/app/source/test-source.ts, and tsconfig.worker.json, and it changes angular.json and src/app/app.ts.
16. Update the README with what the client shows, the test source query settings with their defaults and ranges, and a stress test example URL. This step changes README.md at the repo root.
17. Add entries for this feature to the three logs. This step changes docs/assumptions.md, docs/trade-offs.md, and docs/ai-changes.md.
18. Run every check in validation.md and fix the failures.
