  - No spaces makes each batch 20 percent smaller at no extra cost. The client
    still gets a plain JSON array.
  - Base64 formats are smaller, but they break R2. They also make the browser
    slower. In Node 22, decoding took 0.4 to 0.6 ms per batch, against 0.09 ms
    for JSON.parse. I did not test the newer Uint8Array.fromBase64, which could
    be faster.
  - Gzip does little on its own, because random numbers do not compress well.
    Starlette's built-in gzip also skips text/event-stream, because it holds
    back the response. To add it, you would need to write per-event gzip with
    one compressor for each client.
  - Sorted plus gzip is the only big saving that keeps the JSON array. It comes
    to 1,768 bytes, 7 percent of the original. The client only counts values
    into cells, so their order does not matter. Its cost is the custom gzip
    layer above, and I do not know if the load balancer or CDN in feature 5 will
    pass it through unchanged. It could be a later task.
  - Counts for each value is the smallest format, but the brief asks for an
    array of random integers.
