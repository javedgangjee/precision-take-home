# Feature 7 plan: Settings Display

The steps follow the answers to G1 to G7 in requirements.md.

1. Let the broadcaster keep the settings packet. The broadcaster takes the settings at start. It keeps the packet as one encoded string and keeps a change counter. `update`, `pause`, and `resume` build the packet again and add 1 to the counter when the state changes. A change also puts a wake item in each subscriber queue that is empty, so a stream with no batches still wakes. The wake item is not a batch and takes no sequence number. The packet and the admin response share one model. This step changes backend/app/broadcaster.py, backend/app/admin.py, and backend/app/main.py.
2. Send the settings packet on the stream. The stream route keeps the counter value of the last packet it sent. Before it waits for the next queue item, it sends the packet with `event: update` and no `id` when the counter differs. The first pass sends the packet as the first event. The route sends a batch as before and sends nothing for a wake item. This step changes backend/app/main.py.
3. Write the backend tests, and update the feature 2 and feature 6 stream tests that read the first event, because the first event is now the settings packet. This step changes backend/tests/test_broadcaster.py and backend/tests/test_stream.py.
4. Add the missed batch counter. It takes each batch id and returns the count, and a reset sets the count to 0 and keeps the last id. This step creates frontend/src/app/source/missed-batches.ts and frontend/src/app/source/missed-batches.spec.ts.
5. Add the `paused` state, the settings signal, and the missed batch count signal to the stream status. This step changes frontend/src/app/source/stream-status.ts.
6. Let the server source read the settings packet and the batch ids. It listens for the `update` event, writes the three settings to the stream status, and sets the state to Paused or Live. The watchdog does not run while the state is Paused. Each batch passes its id to the missed batch counter, and the counter lives as long as the service, so it spans a reconnect. The server source resets the counter when N changes. A drop during a pause sets the state to Reconnecting. This step changes frontend/src/app/source/server-source.ts and frontend/src/app/source/server-source.spec.ts.
7. Let the test source write its three settings to the stream status. This step changes frontend/src/app/source/test-source.ts and frontend/src/app/source/test-source.spec.ts.
8. Add the Paused look to the badge. The badge uses the neutral tone and the `pause` icon, and the Google Fonts link adds `pause` to its icon list. This step changes frontend/src/app/panel/stream-badge.ts, frontend/src/app/panel/stream-badge.spec.ts, and frontend/src/index.html.
9. Add four readouts to the side panel below Frame rate. They are Missed batches, Samples per second, Batch interval, and Max value. This step changes frontend/src/app/panel/side-panel.ts, frontend/src/app/panel/side-panel.html, frontend/src/app/panel/side-panel.scss, and frontend/src/app/panel/side-panel.spec.ts.
10. Update the README. The Backend stream section describes the settings packet. The Admin API section drops the note that the client has no Paused state. The Client section describes the Paused badge, the Missed batches readout, and the three settings readouts. This step changes README.md.
11. Add entries for this feature to the three logs. This step changes docs/assumptions.md, docs/trade-offs.md, and docs/ai-changes.md.
12. Run every check in validation.md and fix the failures.
